# Комплект проектной документации

**Текущая версия комплекта: 0.21.21** — это версия приложения из `app/package.json`, единственного места, где номер объявлен.

**Версия выпускается одной командой** `pnpm version:set 0.20.55` (или `patch` / `minor` / `major`) из каталога `app`: она пишет номер в корневой манифест и в титул этого документа. Больше править ничего не нужно — внутренние манифесты версии не объявляют, `CORE_VERSION` и `APP_VERSION` читают номер через `app/packages/core/src/version.ts`, а формат журнала повтора (`REPLAY_FORMAT_VERSION`) и версия боевых правил (`RULES_VERSION`) от номера приложения независимы (как `SAVE_FORMAT_VERSION`) — тесты сверяются с манифестом, а не с литералом. Согласованность проверяет `app/scripts/check-version-consistency.mjs` вместе с визуальным аудитом `audit:visual` (команда `pnpm check:versions`); он же не пропустит литерал версии в исходниках и лишнюю версию в дочернем манифесте.

Настоящий комплект — нормативное описание текущего состояния проекта. Карта документов, каталогов кода и владельцев тем — в [project-map.md](project-map.md). При расхождении формулировок применяется документ, за которым закреплена предметная область. Числовые значения баланса, не указанные здесь явно, хранятся только в JSON5 и проверяются схемами Zod.

### Инварианты

1. Живая сущность занимает ровно одну клетку. Сущностей на несколько клеток не существует.
2. Правила тактического боя исполняет только ведущий участник (host).
3. Интерфейс и средство отображения не изменяют игровое состояние напрямую.
### Быстрая проверка комплекта

После установки зависимостей из `doc/operations.md` рекомендуется выполнять
проверки в таком порядке:

```bash
cd app
pnpm check:versions
pnpm typecheck
pnpm test
```

`check:versions` не заменяет типизацию и тесты: он только обнаруживает
нарушение единого источника версии — расхождение манифеста, констант,
документации и литералов в исходниках.
