# Модель исполнения

Предмет ведения: исполнительное представление сущностей и поля (`EntityState`), словари, системы ядра. Не содержит формул боя и макетов экранов.

Реализация: `app/packages/core/src/types.ts`, `kernel.ts`. Правила изменения значений — «Игровые правила». Поля записей — «Схема конфигурации». Выгрузка — «Контракты обмена».

---

## 1. Обязательные правила среды

1. Сущность есть типизированный объект (`EntityState`) с числовыми, логическими и строковыми полями. Строковые идентификаторы записей хранятся непосредственно в полях сущности (`configId`, `weaponIds`, `skillIds`); отдельного словаря индексов не ведётся.
2. Логический признак без величины представляется булевым полем-меткой (`dead`, `flying`, `hidden`, `overwatch`, `defending`). Запрещается кодировать такие признаки полями вида «равно единице».
3. Живая сущность имеет ровно одну клетку положения и занимает ровно одну клетку. Поля размера, ширины и высоты области отсутствуют и не вводятся.
4. Ярус поверхности, признак ямы, признак глухой стены и признак зоны эвакуации принадлежат массиву клеток поля, а не исполнительной среде сущностей. В среде хранится только то, что перемещается, разрушается или носит состояния.
5. Среда не хранит вычисляемых признаков: фланговый охват вычисляется для пары сущностей в момент разрешения атаки и не сохраняется.

---

## 2. Словари

- **Записи конфигурации** (`units`, `weapons`, `skills`, `items`): внешние таблицы пакета `@bylina/content`, проверяются схемами Zod. Сущность ссылается на них строками-идентификаторами.
- **Владельцы** (`owner`): целое число. `0` — нейтральная принадлежность (среда, укрытия); положительные значения — участники и сторона, управляемая алгоритмом (в текущей версии `1` — игрок, `2` — Нави; состязательный режим допускает произвольное число участников). Порядок хода строится по живым владельцам по возрастанию.
- **Состояние умений** (`skillCooldowns`, `skillUses`): внешние таблицы сущности по строковому идентификатору умения: `cooldown` — оставшиеся ходы перезарядки, `uses` — число применений за бой. Таблица внешняя, поскольку число умений задаётся конфигурацией и меняется от сущности к сущности. Она входит в полный снимок ведущего и сокращённый снимок владельца.

Числовые характеристики при создании сущности копируются из записи конфигурации в поля сущности. Дальнейшее изменение характеристик в бою выполняется ядром, а не повторным чтением записи, за исключением справки по оружию и умениям: оружие и умения с сущности не копируются и читаются по идентификаторам записи.

## 3. Сущность `EntityState`

### 3.1. Отождествление

```typescript
id: number;          // целочисленный идентификатор сущности
configId: string;    // идентификатор записи юнита (либо "cover")
owner: number;       // 0 — среда; положительные — участники
```

### 3.2. Положение

```typescript
x: number;
y: number;
z: number;            // ярус поверхности 0…2
dir: number;          // 0 север, 1 восток, 2 юг, 3 запад
```

Поля флангового охвата не существует: охват вычисляется для пары сущностей в момент разрешения атаки.

### 3.3. Боевые величины

```typescript
ap: number;           // текущий запас очков действия
maxAp: number;        // максимум очков действия
mobility: number;     // очки передвижения на одно очко действия
hp: number;
maxHp: number;
aim: number;          // может быть отрицательным
defense: number;
will: number;         // ≥ 0
vision: number;       // базовая дальность обзора
movementSpent: number; // накопленная стоимость добровольного движения в текущем ходу стороны; 0…2×mobility
```

### 3.4. Оружие и умения

```typescript
weaponId: string;            // текущее оружие; сохраняется для совместимости снимков 0.7.x
weaponIds: string[];         // все доступные юниту записи оружия
skillIds: string[];          // все доступные юниту активные умения
skillCooldowns: Record<string, number>; // перезарядка по идентификатору умения
skillUses: Record<string, number>;      // число применений за текущий бой
```

### 3.5. Среда как сущность

```typescript
coverType: 0 | 1 | 2; // 2 — полное, 1 — неполное, 0 — не укрытие
edge?: 0 | 1 | 2 | 3; // 0=N, 1=E, 2=S, 3=W; отсутствует у целоклеточного укрытия
obstacle: boolean;    // препятствие: у бойцов и целоклеточных укрытий
```

Яма, глухая стена и зона эвакуации в сущность не входят — они признаки клеток поля.

### 3.6. Метки состояний

```typescript
dead: boolean;
overwatch: boolean;
defending: boolean;
flying: boolean;
hidden?: boolean;
decoy?: boolean;          // не наносит урон, является допустимой целью
countsForElimination?: boolean; // учитывается ли сущность в условии уничтожения стороны
fleeHp?: number;          // пороговый уход (§15.6)
camouflageMinCover?: boolean;
providesCamouflage?: boolean;
timedLife?: number;       // ограниченное существование призыва/иллюзии
poison?: { damagePerTurn: number; turnsLeft: number };
panic?: { sourceId: number; turnsLeft: number };
immobileTurns?: number;
rosterIndex?: number;     // индекс бойца в составе высадки кампании (только бойцы дружины)
```

## 4. Архетипы

**Боец стороны** (герой, рядовой противник, генерал, призванный зверь, иллюзия):  \
поля отождествления, положения, боевых величин, оружия и умений, `obstacle: true`. По записи конфигурации дополнительно: `flying`, `hidden`, `timedLife`, `decoy`. Ядро во время боя временно устанавливает `overwatch` и `defending`.

Иллюзия получает `maxHp = 1` согласно записи.

**Укрытие:**  \
`id`, `configId`, `owner: 0`, положение, `coverType`, `edge`, `hp = 2`. `obstacle: true` устанавливается только целоклеточному укрытию; граневое укрытие клетку не занимает: его полная ступень блокирует пересечение указанной грани, неполная увеличивает стоимость. Признак глухой стены на эту сущность не устанавливается.

**Поле боя** как сущность не создаётся.

## 5. Системы

Система — логический блок ядра (`createTacticsKernel`), отбирающий сущности по признакам и изменяющий их поля. Новое правило состояния оформляется новой меткой и новым блоком, а не дополнительным полем в боевых величинах.

Порядок вызова в начале хода стороны задан документом «Игровые правила», раздел 16.

| Система | Читает | Пишет |
|---|---|---|
| PoisonSystem | `hp`, `poison`, отсутствие `dead` | `hp`, `poison`, `dead` |
| TimedLifeSystem | `timedLife`, `owner` | удаление сущности |
| OverwatchResetSystem | `overwatch`, `owner` | снятие `overwatch` |
| DefendingResetSystem | `defending`, `owner` | снятие `defending` |
| SkillCooldownSystem | `owner`, `skillCooldowns` | уменьшение ненулевых `cooldown` на 1 |
| ActionRefillSystem | `ap`, `movementSpent`, отсутствие `dead` | `ap`, `movementSpent = 0` |
| PanicSystem | `panic`, `panic.sourceId`, положение | положение, `ap` |
| CommandSystem | команда, соответствующие поля | по виду команды |
| ThresholdSystem | `hp`, запись `fleeHp` | удаление сущности |
| DeathSystem | `hp ≤ 0` | `dead`, снятие `obstacle` и боевых меток |
| ObjectiveSystem | положение носителя, клетки `homeOwner` | событие завершения сражения |

Запрос перемещаемых юнитов: наличие `ap`, отсутствие `dead`, `panic`, `immobileTurns`, при `ap > 0`.

Запрос юнитов, способных действовать с места: тот же набор без исключения `immobileTurns`.

---

## 6. Выгрузка

Функция выгрузки обходит сущности и массив клеток поля и формирует снимок, описанный в документе «Контракты обмена». Идентификаторы записей передаются строками.

Полный снимок строится только у ведущего. Ведомому передаётся снимок после исключения сведений, не принадлежащих его стороне, по правилам документа «Контракты обмена»: неразведанные клетки опускаются либо передаются без признаков; чужие скрытые сущности исключаются.
