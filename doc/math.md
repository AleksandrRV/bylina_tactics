# Игровая математика
## «Былина: Тьма Кощея», версия 1.1

Предмет ведения: однозначные алгоритмы тактического слоя. Художественное описание ролей в этот документ не входит. Поля конфигурации, на которые ссылаются алгоритмы, определены в документе «Схема конфигурации».

Во всех сравнениях координат используется целочисленная арифметика, если не оговорено иное. Источник случайности — исключительно генератор, описанный в разделе 1.

---

## 1. Генератор псевдослучайных чисел

Применяется алгоритм Mulberry32. Начальное значение — целое число без знака шириной 32 бита. В снимке состояния десятичными строками передаются как начальное значение, так и текущее внутреннее состояние; восстановление снимка продолжает последовательность с текущего состояния.

Запрещается использовать любой иной источник случайности, включая стандартную функцию среды исполнения.

Шкала вероятности: целые числа от 1 до 100 включительно. Испытание: очередное значение генератора на отрезке [1, 100]. Успех: полученное число меньше либо равно проверяемой вероятности.

После суммирования модификаторов значение округляется до ближайшего целого числа (`0,5` округляется вверх), затем ограничивается отрезком [1, 100].

Если действие признано недопустимым (раздел 6), испытание не проводится. Недопустимость не выражается вероятностью 0 процентов и не отображается как «нулевой шанс».

Порядок испытаний при атаке, требующей попадания: сначала попадание, при успехе — критический удар, затем величина урона. Каждое испытание потребляет ровно одно очередное значение генератора в указанном порядке.

## 2. Пространство

### 2.1. Система координат

Поле — прямоугольная решётка клеток. Клетка задаётся тройкой целых чисел `(x, y, z)`.

- Ось X направлена на восток; значения возрастают вправо. Допустимые значения: `0 … ширина − 1`.
- Ось Y направлена на юг; значения возрастают вниз. Допустимые значения: `0 … высота − 1`.
- Ось Z направлена вверх и обозначает ярус поверхности клетки. Допустимые значения: 0 (нижний), 1 (средний), 2 (верхний).

Яма и глухая стена не кодируются значением Z. Они хранятся как логические признаки клетки: `pit` и `blockLOS`.

Соседи клетки по горизонтали — восемь клеток с `max(|Δx|, |Δy|) = 1` и `(Δx, Δy) ≠ (0, 0)`.

### 2.2. Горизонтальное расстояние

```
DistH(A, B) = floor( sqrt( (B.x − A.x)² + (B.y − A.y)² ) )
```

Составляющая Z в это расстояние не входит. Для диагонально смежных клеток `DistH = 1`. Для одной и той же клетки `DistH = 0`.

Ближний бой допустим только при одновременном выполнении условий: `DistH ≤ 1` и `|A.z − B.z| ≤ 1`.

### 2.3. Ориентация

Ориентация принимает одно из четырёх значений. Единичные векторы на плоскости XY:

| Значение | Направление | Вектор |
|---|---|---|
| 0 | Север | (0, −1) |
| 1 | Восток | (1, 0) |
| 2 | Юг | (0, 1) |
| 3 | Запад | (−1, 0) |

После шага из клетки P в клетку Q ориентация устанавливается по вектору `(Q.x − P.x, Q.y − P.y)`: выбирается кардинальное направление с наибольшей проекцией; при равенстве абсолютных величин составляющих сохраняется прежняя ориентация, если обе составляющие ненулевые и равны по модулю — предпочтение отдаётся оси X.

## 3. Модификатор высоты для дальности и зрения

Модификатор применяется исключительно:

- к дистанционной атаке оружием;
- к умению, в конфигурации которого указана дальность (`range`) и не установлен признак ближнего действия;
- к расчёту поля зрения.

Модификатор не применяется к ближнему бою, к перемещению, к действию, целью которого является сам действующий юнит.

```
HeightRangeMod(zFrom, zTo) =
    +1,  если zFrom > zTo;
    −1,  если zFrom < zTo;
     0,  если zFrom = zTo.

EffectiveRange(from, to, base) = max(0, base + HeightRangeMod(from.z, to.z))

InRange(from, to, base) ⇔ DistH(from, to) ≤ EffectiveRange(from, to, base)
```

Любая ненулевая разность ярусов даёт поправку ровно в одну клетку, а не в величину разности. Юнит на ярусе 2 относительно цели на ярусе 0 получает `+1`, а не `+2`.

## 4. Занятость

Клетка считается занятой, если в ней находится сущность, обладающая компонентом препятствия (`ObstacleTag`).

Гибель снимает компонент препятствия. Несколько погибших в одной клетке допускаются. Живые сущности совмещаться не могут.

Правила прохода:

| Содержимое клетки | Проход сквозь клетку | Завершение перемещения |
|---|---|---|
| Свободна, не яма | Разрешён | Разрешено |
| Союзник | Разрешён | Запрещено |
| Противник | Запрещён | Запрещено |
| Целоклеточное укрытие | Запрещён | Запрещено |
| Граневое укрытие в клетке | Разрешён, с учётом пересекаемой грани | Разрешено |
| Глухая стена (`blockLOS`) | Запрещён | Запрещено |
| Яма, нет признака полёта | Запрещён | Запрещено |
| Яма, есть признак полёта | Разрешён | Разрешено |
| Только тела погибших | Разрешён | Разрешено |

Признак полёта не позволяет проходить сквозь глухую стену, противника, целоклеточное укрытие или полную защищённую грань.

Граневое укрытие хранится на одной из четырёх границ клетки: 0 — север, 1 — восток, 2 — юг, 3 — запад. Одна физическая граница может быть описана со стороны любой из двух соседних клеток. Полное граневое укрытие запрещает переход через эту границу. Неполное разрешает переход и добавляет 1 к стоимости ребра. На диагональном шаге проверяются обе пересекаемые кардинальные границы; если обе неполные, дополнительная стоимость остаётся равной 1, а не 2.

## 5. Перемещение

### 5.1. Стоимость ребра

Подвижность (`mobility`) — число очков передвижения, доступных за одно очко действия.

Стоимость шага в диагональную соседнюю клетку равна стоимости шага в ортогональную. Обход угла запрещён: шаг из `(x1, y1)` в `(x2, y2)` по диагонали допустим только если обе клетки `(x2, y1)` и `(x1, y2)` разрешают проход сквозь себя (таблица раздела 4) при ярусе исходящей клетки.

Стоимость ребра из A в соседнюю B определяется первой подходящей строкой:

| Условие | Очки передвижения |
|---|---|
| B вне поля | Ребро отсутствует |
| У B признак `blockLOS` | Ребро отсутствует |
| У B признак `pit` и у идущего нет полёта | Ребро отсутствует |
| В B противник или целоклеточное укрытие | Ребро отсутствует |
| Пересекается полное граневое укрытие | Ребро отсутствует |
| `\|B.z − A.z\| = 2` и у идущего нет полёта | Ребро отсутствует |
| У идущего есть полёт | 1 |
| `B.z = A.z` либо `B.z = A.z − 1` | 1 |
| `B.z = A.z + 1` | 2 |

Союзник в B не запрещает ребро; стоимость считается по строкам о ярусе либо полёте. После выбора базовой стоимости к ней прибавляется 1, если переход пересекает хотя бы одно неполное граневое укрытие.

### 5.2. Поиск пути

Применяется алгоритм A* по рёбрам раздела 5.1. Клетка назначения не может нарушать столбец «завершение перемещения» таблицы раздела 4.

При равенстве оценок выбирается клетка, достижимая кардинальным шагом предпочтительнее диагонального; при повторном равенстве — меньшая координата X, затем меньшая Y. Ведущий всегда пересчитывает путь самостоятельно. Последовательность клеток, присланная ведомым, не является основанием для изменения состояния.

Пусть S — сумма стоимостей рёбер найденного пути, M — подвижность юнита.

- при `S ≤ M` действие расходует одно очко действия;
- при `M < S ≤ 2M` действие расходует два очка действия (рывок);
- при `S > 2M` путь недопустим.

Ядро накапливает стоимость всех добровольных перемещений юнита в текущем ходу стороны. Новое перемещение допустимо только если накопленная стоимость вместе с S не превосходит `2M`. Ограничение действует и для юнитов с максимумом ОД больше двух; принудительное смещение в накопление не входит. Счётчик обнуляется в начале следующего хода стороны.

### 5.3. Ограничение связности карты

Генератор карты обязан обеспечить существование пути с конечной суммой стоимостей между каждой клеткой появления стороны игрока и каждой клеткой появления стороны противника. Разность ярусов, равная двум, не должна разделять эти зоны без обхода.

## 6. Допустимость действия

Действие отклоняется без изменения состояния и без обращения к генератору, если нарушено хотя бы одно условие.

Общие условия:

1. Сейчас ход стороны, которой принадлежит действующий юнит.
2. Юнит существует, не обладает признаком гибели и не обладает признаком паники.
3. Текущий запас очков действия не меньше стоимости из записи оружия или умения. Если стоимость не указана, принимается 1.
4. Цель (сущность или клетка) существует и лежит в пределах поля.
5. Сущность с признаком конфигурации `decoy` не может быть действующим лицом атаки или умения с разрешением «атака».

Дополнительно для перемещения: путь удовлетворяет разделу 5; суммарная стоимость в очках действия не превышает текущего запаса.

Дополнительно для оружия или умения категории `melee`: `DistH ≤ 1` и `|Δz| ≤ 1`.

Дополнительно для оружия или умения категории `ranged`: выполняется `InRange` (раздел 3); если в записи не снят признак требования линии наблюдения, линия наблюдения существует (раздел 7).

Дополнительно для умения, создающего сущность: клетка назначения удовлетворяет столбцу завершения перемещения таблицы раздела 4.

Дополнительно для умения с признаком извлечения: юнит находится в клетке поля с признаком зоны эвакуации.

Алгоритм управления противником не формирует команду умения с `applyStatus` для цели, у которой соответствующее состояние уже активно. Если умение накладывает несколько состояний, наличие любого из них исключает цель для этого умения. Это правило выбора команды не запрещает человеку осознанно обновить состояние, если команда иначе допустима.

## 7. Линия наблюдения

Отрезок строится из точки `(A.x + 0,5; A.y + 0,5; A.z + 0,5)` в точку `(B.x + 0,5; B.y + 0,5; B.z + 0,5)`.

Строится суперпокрытие двух видов, кроме клеток A и B:

- `full` — отрезок пересекает внутренность клетки;
- `glancing` — отрезок проходит точно через угол клетки, не входя в её внутренность. При проходе через общий угол в суперпокрытие включаются обе боковые клетки с таким признаком.

Живые сущности, тела погибших и укрытия отрезок не прерывают.

Для каждой промежуточной клетки C:

1. Пусть `rz` — координата Z отрезка в ближайшей к центру `(C.x + 0,5; C.y + 0,5)` точке соответствующего отрезку участка клетки.
2. Вычисляется `h = C.z − rz`. При `h > 1` поверхность клетки прерывает отрезок (луч уходит в склон или толщу яруса). При `0 < h ≤ 1` линия сохраняется, а возвышение даёт укрытие по разделу 9.4; для `glancing` применяется половинная ступень такого препятствия.
3. Если у клетки `full` установлен признак `blockLOS`, линия прерывается.
4. Одна клетка `glancing` с `blockLOS` линию не прерывает, но считается полным укрытием и даёт вычет 50 к попаданию.
5. Если луч в одной вершине касается двух соседних клеток `glancing` с `blockLOS`, линия прерывается. Клетки считаются соседними при `max(|Δx|, |Δy|) ≤ 1`.

Линия наблюдения существует, если ни одна промежуточная клетка не прервала отрезок. Правила `glancing` детерминированы и одинаковы для зрения, атаки и предпросмотра.

Действие, целью которого является сам действующий юнит, линии наблюдения не требует.

## 8. Поле зрения и скрытность

### 8.1. Наблюдаемость клетки

Клетка T наблюдается юнитом U тогда и только тогда, когда одновременно:

1. Выполняется `InRange(U, T, vision)`, где `vision` — значение из характеристик юнита; поправка высоты берётся по разделу 3.
2. Существует линия наблюдения из U в T.
Обзор стороны есть объединение клеток, наблюдаемых всеми живыми юнитами этой стороны. Ориентация обзор не ограничивает. Наличие скрытой сущности не скрывает саму местность клетки. Скрытая сущность не включается в сведения чужой стороны, пока не выполнено хотя бы одно условие: `DistH(U, T) ≤ 1`; признак скрытности уже снят; применяется умение с признаком обнаружения.

### 8.2. Снятие скрытности

Признак скрытности снимается при первом из событий:

- сущность выполнила атаку или активное умение;
- существует живой противник с `DistH ≤ 1`;
- по сущности или по её клетке применено умение с признаком обнаружения.

После снятия признак не восстанавливается, пока иное умение явно его не наложит вновь.

### 8.3. Туман войны как сведения стороны

Клетка относится к одному из трёх разрядов для стороны:

- никогда не наблюдалась — сведения о местности отсутствуют;
- наблюдалась ранее и не наблюдается сейчас — известен рельеф, неизвестны чужие юниты;
- наблюдается сейчас — известны рельеф и находящиеся в клетке сущности, не скрытые по разделу 8.2.

## 9. Укрытие и фланговый охват

Расчёт выполняется для упорядоченной пары (атакующий A, цель T) в момент разрешения действия. Отдельного постоянного признака «охвачен с фланга» на сущности не существует.

### 9.1. Кандидаты

Для целоклеточного укрытия рассматриваются сущности в клетках C, для которых `DistH(T, C) = 1` и `|T.z − C.z| ≤ 1`.

Граневое укрытие является кандидатом, если цель находится в клетке укрытия либо в клетке по другую сторону указанной грани и `|T.z − C.z| ≤ 1`. Таким образом, одно физическое граневое укрытие одинаково работает независимо от того, к какой из двух соседних клеток привязана его запись.

### 9.2. Укрытие на направлении выстрела

Пусть `sx = sgn(A.x − T.x)`, `sy = sgn(A.y − T.y)`, где `sgn(0) = 0`.

Клетка укрытия C с относительным вектором `(dx, dy) = (C.x − T.x, C.y − T.y)` лежит на направлении выстрела, если она входит в следующий набор:

- при `sx ≠ 0` и `sy ≠ 0`: `(sx, 0)`, `(0, sy)`, `(sx, sy)`;
- при `sx ≠ 0` и `sy = 0`: `(sx, 0)`, `(sx, 1)`, `(sx, −1)`;
- при `sx = 0` и `sy ≠ 0`: `(0, sy)`, `(1, sy)`, `(−1, sy)`.

Целоклеточное укрытие проверяется по набору выше. Граневое укрытие лежит на направлении выстрела только тогда, когда атакующий и цель находятся по разные стороны защищённой границы; для диагонального выстрела учитывается любая из двух входных границ клетки цели.

Глухая стена в соседней с целью клетке направления считается кандидатом полного укрытия, если сама клетка стены не является промежуточной клеткой `full`, уже прервавшей линию наблюдения.

Из укрытий на направлении выбирается наибольшая ступень: 2 (полное) предпочтительнее 1 (неполное). Направленное укрытие, обнулённое перспективой высоты, не создаёт фланговый охват.

### 9.3. Эффективная ступень укрытия с учётом высоты

Эффективная ступень укрытия определяется с учётом высоты атакующего и защищающегося:

1. Стена (blockLOS) всегда считается полным укрытием (ступень 2).
2. Перспектива защищающегося: разница `defenderZ − coverZ`:
   - ≤ 0: обычная эффективность (ступень не снижается).
   - = 1 (укрытие на 1 ниже защищающегося): полное → полу (1), полу → игнор (0).
   - ≥ 2 (укрытие на 2+ ниже защищающегося): полное → игнор (0), полу → игнор (0).
3. Перспектива атакующего: разница `attackerZ − coverZ`:
   - ≤ 0: обычная эффективность.
   - = 1 (атакующий на 1 выше укрытия): полное → полу (1), полу → игнор (0).
   - ≥ 2 (атакующий на 2+ выше укрытия): полное → игнор (0), полу → игнор (0).
4. Итоговая эффективная ступень: минимум из двух перспектив.

### 9.4. Перепад высот как укрытие

Возвышение между атакующим и защищающимся считается укрытием:

- Высота +1 над атакующим → полуукрытие (ступень 1).
- Высота +2 над атакующим → полное укрытие (ступень 2).

Учитывается только если возвышение на линии огня (между атакующим и защищающимся).

### 9.5. Модификатор укрытия

| Эффективная ступень | Вычет из вероятности попадания |
|---|---|
| 0 (нет укрытия) | 0 |
| 1 (полуукрытие) | 25 |
| 2 (полное укрытие) | 50 |

Исключения, применяемые после таблицы:

- умение или оружие с признаком игнорирования неполного укрытия обращает вычет 25 в 0; вычет 50 сохраняется;
- ближний бой обращает вычет целоклеточного укрытия и рельефа в 0; граневое укрытие, непосредственно разделяющее соседних участников, сохраняет свой вычет. Полная грань запрещает обычную ближнюю атаку, а разрушающее оружие обрабатывает её по разделу 12.1; проверка флангового охвата для критического удара сохраняется;

Цель с признаком полёта укрытий не имеет: вычет равен 0, фланговый охват не устанавливается.

### 9.6. Фланговый охват и открытая местность

Цель охвачена с фланга относительно данного выстрела, если множество кандидатов раздела 9.1 непусто и ни один кандидат не лежит на направлении по разделу 9.2.

Если множество кандидатов пусто, цель находится на открытой местности: вычет укрытия равен 0, фланговый охват не устанавливается.

Признак маскировки (`camouflageMinCover` и `providesCamouflage`) не является направленным укрытием: он не входит в множество кандидатов раздела 9.1, не влияет на определение флангового охвата и применяется независимо от него. Вычет маскировки обращается в 0 только признаком игнорирования неполного укрытия.

## 10. Разрешение атаки

### 10.1. Вероятность попадания

Действие должно быть допустимо по разделу 6. Затем:

```
вероятность = меткость_юнита
            + модификатор_оружия
            + модификатор_высоты
            − защита_цели
            − 25, если цель находится в защитной стойке
            − вычет_укрытия
            − вычет_дальности
```

Результат ограничивается отрезком [1, 100] и подвергается испытанию.

Модификатор высоты:

- `A.z > T.z` — прибавить 20;
- `A.z < T.z` — вычесть 20;
- иначе — 0.

Этот модификатор не заменяет раздел 3 и не влияет на допустимость клетки.

Вычет дальности берётся из записи оружия. Если задано поле `closeRangePenalty` и `DistH < distHLessThan`, применяется указанный в записи вычет. Ярус в этот вычет не входит.

### 10.2. Критический удар

Испытание проводится только после успешного попадания.

```
вероятность = базовое_значение_оружия
            + (40, если установлен фланговый охват по разделу 9.6)
            + сумма модификаторов умений
```

### 10.3. Урон

Базовая величина — целое число, равномерно выбранное генератором на отрезке от минимума до максимума оружия включительно. При критическом ударе к ней прибавляется премия оружия.

Если цель находится в защитной стойке, после прибавления критической премии из урона вычитается 2; нижняя граница результата равна 0. Стойка уменьшает только урон атак оружием и активных умений с разрешением «атака». Урон от столкновения, падения в яму, отравления и иных внутренних срабатываний не уменьшается.

В текущей версии запас брони равен нулю. На будущее закреплена формула `max(1, урон − броня)`; будущая броня применяется после критической премии, а уменьшение стойки — последним, с собственной нижней границей 0.

### 10.4. Атака по укрытию

Если целью указана сущность укрытия, испытание попадания не проводится. Действие допустимо при выполнении раздела 6. Если разрушающая сила действующего оружия или умения не меньше 1, применяется раздел 12 ровно один раз. В противном случае действие недопустимо.

### 10.5. Умение без испытания попадания

Умение с способом разрешения «автоматический» при допустимости немедленно применяет перечисленные в конфигурации следствия (лечение в пределах максимума здоровья, наложение или снятие состояния, создание сущности, перемещение без маршрута, извлечение). Воскрешение костяка требует тело погибшего юнита указанной записи в целевой клетке; тело удаляется и заменяется новой живой сущностью стороны применившего умение. Воскрешённый костяк появляется с 1 единицей текущего здоровья независимо от `maxHealth` записи.

Умение с способом разрешения «проверка воли»:

```
вероятность = clamp(сила_умения − воля_цели, 1, 100)
```

При успехе накладывается указанное состояние.

## 11. Область действия

Клетка эпицентра должна быть допустимой целью умения (раздел 6).

Клетка P входит в область, если `DistH(эпицентр, P) ≤ радиус` и `|эпицентр.z − P.z| ≤ 1`.

Каждая живая сущность противника (либо каждая сущность указанного в конфигурации фильтра) в области разрешается отдельно, в порядке возрастания идентификатора сущности, полным циклом раздела 10 либо автоматическим следствием.

## 12. Разрушение укрытия

Применяется, если разрушающая сила не меньше 1 и выбрана сущность укрытия либо на направлении выстрела по разделу 9.2 есть укрытие цели, а действие обладает признаком поражения среды.

```
ступень := ступень − 1
```

При переходе 2 → 1 укрытие становится неполным. При переходе 1 → 0 с сущности снимаются компоненты укрытия и препятствия.

Одно применение уменьшает ступень ровно на единицу независимо от величины разрушающей силы. Оружие с разрушающей силой 0 среду не изменяет.

Укрытие на направлении выстрела, не являющееся целью действия, повреждается только при попадании атаки в цель: промах среду не изменяет. Прямая атака по сущности укрытия (раздел 10.4) и удар через грань (раздел 12.1) повреждение среды от испытания попадания не зависят.

### 12.1. Удар палицей через граневое укрытие

Если юнит атакует врага оружием категории `melee` с `envDmg ≥ 1` и между участниками на направлении удара находится разрушаемое граневое укрытие, среда разрешается **до** испытания попадания:

1. Выбирается наибольшая ступень направленного граневого укрытия; при равенстве — меньший идентификатор сущности.
2. Ступень уменьшается ровно на одну и немедленно формируется событие изменения укрытия.
3. Вероятность попадания вычисляется уже по оставшейся эффективной ступени с учётом высоты. Поэтому неполное укрытие исчезает и не даёт вычета, а полное становится неполным и обычно сохраняет вычет 25.
4. Независимо от попадания изменение среды сохраняется. При попадании из итогового урона по врагу дополнительно вычитается значение `envDmg`, но не ниже 0: эта часть импульса была принята окружением. Уменьшение защитной стойки применяется отдельно и складывается с данным вычетом.

Правило относится к палице и другим явно настроенным разрушающим оружиям ближнего боя. Оно не превращает обычное оружие с `envDmg = 0` в средство атаки сквозь полную грань. В наборе событий изменение укрытия располагается раньше разрешения боя.

## 13. Принудительное смещение

Исходные клетки: атакующий A, цель T.  
`dx = sgn(T.x − A.x)`, `dy = sgn(T.y − A.y)`. Клетка назначения D = `(T.x + dx, T.y + dy, z клетки поля)`.

Если обе составляющие ненулевые и завершение перемещения в D запрещено, проверяется сначала клетка только по оси с большей абсолютной разностью координат A и T, затем по второй оси; при равенстве первой проверяется ось X. Если назначение так и не найдено, фиксируется столкновение. Полное граневое укрытие на пересекаемой границе также делает назначение запрещённым; неполное не наносит дополнительного урона и не расходует очков передвижения.

Исходы:

- D вне поля, либо завершение перемещения в D запрещено, либо `|D.z − T.z| = 2` — цель не смещается, ей наносится 2 единицы урона;
- у D признак ямы и у цели нет полёта — цель помещается в D, запас здоровья становится равен 0, причина гибели — падение в яму; защитные состояния не применяются;
- `D.z = T.z − 1` и завершение разрешено — цель помещается в D без дополнительного урона;
- иначе при разрешённом завершении — цель помещается в D.

Смещение не строит маршрут и не оплачивается очками передвижения. Вход в клетку назначения порождает проверку дозора (раздел 14). Промежуточные клетки не рассматриваются.

Перемещение телепортацией подчиняется тому же правилу дозора: проверяется только клетка назначения. Промежуточные клетки не пересекаются и дозор на них не вызывают.

---

## 14. Дозор

Приказ устанавливает признак дозора и обнуляет очки действия юнита.

Ответное действие выполняется при входе живого противника в клетку C, если одновременно:

1. У наблюдающего сохранён признак дозора.
2. Наблюдающий жив и не обездвижен так, что конфигурация запрещает ответное действие (по умолчанию обездвиживание запрещает только шаг, не дозор).
3. Скалярное произведение вектора ориентации наблюдающего и вектора `(C.x − U.x, C.y − U.y)` неотрицательно (передняя полуплоскость, боковые клетки включены).
4. Цель в клетке C допустима для оружия дозора по разделу 6, включая `InRange` с поправкой высоты и линию наблюдения.
5. У цели нет неснятого признака скрытности.

Наблюдающий производит ровно одно ответное действие, после чего признак дозора снимается. Если несколько наблюдающих удовлетворяют условиям для одной и той же клетки, они действуют в порядке возрастания идентификатора. Гибель цели прерывает дальнейшие ответные действия по ней и прерывает её маршрут: она остаётся в клетке гибели.

Движение после выжившего ответного действия продолжается. Тот же наблюдающий повторно не действует. Вступление в последующую клетку может вызвать других наблюдающих.

Начало хода в секторе дозора без входа в новую клетку ответного действия не вызывает. Атака и умение без смены клетки дозор не вызывают.

## 15. Состояния

### 15.1. Отравление

В начале хода стороны-владельца, до восстановления очков действия: из текущего здоровья вычитается указанный урон; счётчик длительности уменьшается на 1; при достижении нуля состояние снимается. Если здоровье стало меньше либо равно нулю, фиксируется гибель по причине отравления.

### 15.2. Ограниченное существование

Применяется к призванным сущностям и иллюзиям. В начале хода стороны-владельца счётчик уменьшается на 1; при достижении нуля сущность удаляется с поля без признака гибели бойца кампании.

Сущность, созданная со счётчиком 1, переживает ход противника и удаляется в начале следующего хода своей стороны, не получая активации.

### 15.3. Паника

Длится до окончания следующего хода стороны цели. В начале этого хода, после восстановления очков действия, исполнительная среда выбирает среди клеток, достижимых за одно очко действия, клетку с наибольшим `DistH` от источника паники и выполняет перемещение в неё по разделу 5. При равенстве `DistH` применяется правило предпочтения раздела 5.2. Если ни одна достижимая клетка не увеличивает `DistH`, юнит остаётся на месте. Остаток очков действия сгорает. Игрок и алгоритм управления этого юнита в этот ход не активируют.

### 15.4. Обездвиживание

Все исходящие рёбра поиска пути отсутствуют. Действия, не требующие смены клетки, допустимы. Счётчик длительности уменьшается в конце хода стороны-владельца; состояние снимается после того, как полностью запретило перемещение в указанном числе ходов.

Признак полёта отменяет обездвиживание только если в конфигурации наложившего умения не установлен запрет этой отмены (поле `affectsFlying` умения; по умолчанию полёт отменяет обездвиживание).

### 15.5. Полёт

Изменяет стоимость рёбер и доступность ям согласно разделам 4 и 5. Не отменяет глухие стены. Цель с полётом обрабатывается по последнему абзацу раздела 9.3.

Утрата признака в клетке с ямой приводит к гибели по причине падения в яму.

### 15.6. Пороговый уход

Если в записи юнита задано поле `fleeHp` и после любого изменения здоровья выполняется `0 < Health.current ≤ fleeHp`, сущность немедленно удаляется с поля с причиной ухода, без признака гибели бойца кампании.

Снижение здоровья до нуля — атакой, отравлением, падением в яму или иной причиной — фиксирует гибель (раздел 15.7) и пороговый уход не применяет. Погибший таким образом генерал или особый противник исключается из кампании окончательно.

### 15.7. Гибель

Устанавливается признак гибели, снимается компонент препятствия, очки действия обнуляются, снимаются дозор, защитная стойка, скрытность и полёт. Сущность перестаёт наблюдать клетки и перестаёт быть допустимой целью атаки.

### 15.8. Защитная стойка

Команда защитной стойки допустима живому действующему юниту при наличии хотя бы одного ОД. Команда устанавливает признак стойки и обнуляет весь текущий запас ОД. Пока признак действует:

- из вероятности попадания по юниту дополнительно вычитается 25;
- итоговый урон каждой попавшей атаки оружием или умением с разрешением «атака» уменьшается на 2, но не ниже 0;
- столкновение, падение в яму, отравление и другие внутренние срабатывания стойку игнорируют.

Признак снимается в начале следующего хода стороны-владельца до восстановления ОД либо немедленно при гибели. Стойка не ограничивает обзор и не считается укрытием; поэтому она не участвует в расчёте флангового охвата.

### 15.9. Перезарядка и предел применений

Умение допустимо только при нулевом текущем счётчике перезарядки и пока число его применений данной сущностью меньше `maxUsesPerBattle`, если предел задан. После принятой команды `USE_SKILL` число применений увеличивается независимо от результата испытания попадания или воли, а счётчик устанавливается в `cooldownTurns`.

Счётчик уменьшается на 1 один раз в начале каждого следующего хода стороны-владельца, после отравления и ограниченного существования. Значение `1` означает, что между двумя применениями проходит один полный ход противника; в начале следующего собственного хода счётчик становится 0. Предел применений не восстанавливается до окончания боя.

Каждое умение без эффекта `spawn` обязано иметь перезарядку от 1 до 5 ходов. Любое умение призыва, создания иллюзии или воскрешения с эффектом `spawn` имеет `maxUsesPerBattle = 1` для каждой владеющей им сущности.

## 16. Порядок начала хода стороны

1. Обработать отравление всех живых юнитов стороны.
2. Обработать ограниченное существование юнитов стороны.
3. Уменьшить ненулевые счётчики перезарядки умений стороны.
4. Снять признаки дозора, если ответное действие не было произведено, и защитной стойки у юнитов стороны.
5. Восстановить очки действия живых юнитов стороны до значения максимума.
6. Обработать панику.
7. Принять команды игрока либо алгоритма управления.

Конец хода стороны наступает по команде завершения либо когда ни один юнит стороны не имеет допустимых действий и сторона не обязана ждать ввода. Неизрасходованные очки действия сгорают; дозор автоматически не устанавливается.

## 17. Переносимый предмет состязательного режима

Предмет не является сущностью с компонентом препятствия и не занимает клетку в смысле раздела 4.

Юнит, завершивший перемещение либо оказавшийся в клетке предмета в результате смещения, становится носителем. Одновременно носителем может быть только одна сущность. Если носитель уже есть, вход другого юнита в ту же клетку не передаёт предмет (клетка носителя занята и недоступна для завершения).

Пока носитель жив, положение предмета совпадает с положением носителя. При гибели носителя предмет остаётся в клетке гибели и не имеет носителя.

Победа по предмету фиксируется в момент, когда носитель находится в клетке с признаком `homeOwner`, равным стороне носителя. Проверка выполняется после каждого перемещения, смещения и начала хода.

Клетки `homeOwner` назначает генератор карты: противоположные края поля, по одному на сторону.
