## 1. Базовые константы и RNG

Вся математика базируется на детерминированном генераторе псевдослучайных чисел (PRNG), чтобы обеспечить синхронизацию в мультиплеере (рекомендуемый алгоритм: `Mulberry32`).
*   Значения шансов (Меткость, Крит) всегда выражаются в процентах от **1 до 100**.
*   Бросок кубика (Roll): `rng.next(1, 100)`.
*   Успех: Если `Roll <= Chance`, действие успешно. (При шансе 80%, значения 1..80 означают попадание).

## 2. Математика Сетки и Перемещения (Grid & Movement)

Поле представляет собой 3D-массив клеток с координатами `(X, Y, Z)`.
*   **X, Y** — горизонтальные оси.
*   **Z** — высота (0: Яма/Низина, 1: Земля, 2: Возвышенность).

### 2.1. Расчет дистанции (Distance)
Для расчета дальности стрельбы и применения АоЕ используется **Евклидова метрика**, округленная до целого вниз:
`Distance = floor( sqrt((X2 - X1)^2 + (Y2 - Y1)^2 + (Z2 - Z1)^2) )`

### 2.2. Поиск пути (Pathfinding A*)
Характеристика `Mobility` (Мобильность) определяет, сколько очков передвижения (Movement Points, MP) есть у юнита на 1 ОД (Очко Действия). *Базовое значение Богатыря = 6*.

**Стоимость шага в соседнюю клетку (включая диагонали):**
*   **Обычный шаг (Z1 == Z2):** Стоимость = 1 MP. (Диагонали стоят 1.4, но для упрощения интерфейса мы округляем их до 1 MP, однако запрещаем "срезать" углы через препятствия).
*   **Шаг вниз (Z2 = Z1 - 1):** Стоимость = 1 MP (Спрыгивание не штрафуется).
*   **Шаг вверх (Z2 = Z1 + 1):** Стоимость = 2 MP (Требует усилий).
*   **Шаг через 2 уровня (Z2 = Z1 +/- 2):** Запрещен (Стоимость = $\infty$).
*   **Шаг в Яму:** Возможен только если юнит имеет статус `Flying` (Баба Яга), иначе клетка непроходима для курсора (но туда можно *столкнуть*).

**Трата ОД (Action Points):**
*   Если сумма MP маршрута $\le$ `Mobility`: тратится **1 ОД**.
*   Если `Mobility` $<$ сумма MP $\le$ (`Mobility` $\times 2$): тратится **2 ОД** (Рывок).

## 3. Линия видимости (Line of Sight - LOS) и Укрытия

Чтобы атаковать врага, между центром клетки атакующего и центром клетки цели должен быть чистый луч (Raycast).

### 3.1. Алгоритм луча
Используется 3D-модификация алгоритма Брезенхэма. Луч строится от `(X1+0.5, Y1+0.5, Z1+0.5)` до `(X2+0.5, Y2+0.5, Z2+0.5)`.
Если луч пересекает клетку с компонентом `ObstacleTag` и высотой Z, превышающей луч, LOS блокируется (цель не видна).

### 3.2. Расчет Укрытия (Cover Status)
Укрытие защищает цель **только если оно находится между Атакующим и Целью**.

**Алгоритм:**
1. Найти 8 соседних клеток вокруг Цели.
2. Отфильтровать те, в которых есть компонент `Cover` (Полуукрытие или Полное).
3. Проверить угол между вектором "Цель -> Атакующий" и вектором "Цель -> Укрытие".
4. Если угол меньше 45 градусов (укрытие находится ровно на пути луча стрельбы), Цель получает бонус укрытия.

## 4. Флангирование (Flanking)

Флангирование происходит, когда Атакующий обходит Укрытие цели.
**Формула:** Если цель прилегает к Укрытию, но алгоритм из п. 3.2 не нашел укрытия на линии огня (угол больше 90 градусов), Цель считается **Открытой (Flanked)**.
*   *Исключение:* Если у Цели вообще нет укрытий поблизости, она просто "На открытой местности" (Exposed), но технически это тот же статус для математики урона.

## 5. Математика Боя (Combat Resolution)

Бой рассчитывается по системе **Двух бросков (2-Roll System)**: сначала проверяется Попадание, затем Крит.

### 5.1. Формула Попадания (Hit Chance)
```text
HitChance = Attacker_Aim + Weapon_Aim_Modifier + Height_Bonus - Target_Defense - Cover_Penalty - Range_Penalty
```
*Все значения зажимаются в диапазон `[1, 100]` после расчетов. Значение `0%` означает невозможность выстрела (кнопка неактивна).*

**Переменные:**
*   `Attacker_Aim`: Базовая меткость (например, Стрелец = 85, Упырь = 65).
*   `Height_Bonus`: Если Атакующий выше Цели (Z1 > Z2) $\rightarrow$ **+20%**. Если ниже (Z1 < Z2) $\rightarrow$ **-20%**.
*   `Target_Defense`: Базовое уклонение цели (обычно 0, у вертких врагов вроде Кикиморы = 10).
*   `Cover_Penalty`:
    *   Нет укрытия / Фланг = **0%**
    *   Полуукрытие (Half Cover) = **-25%**
    *   Полное укрытие (Full Cover) = **-50%**
*   `Range_Penalty`: Зависит от оружия.
    *   *Пищаль:* Без штрафа на дистанции, штраф **-30%** при стрельбе в упор (Distance < 3).
    *   *Палица/Меч (Melee):* Может бить только на Distance <= 1.5. Шанс попадания в ближнем бою игнорирует укрытия.

### 5.2. Формула Критического удара (Crit Chance)
Крит проверяется **только если** бросок на попадание был успешен.
```text
CritChance = Weapon_Base_Crit + Flank_Bonus + Skill_Modifiers
```
*   `Weapon_Base_Crit`: Меч = 10%, Пищаль = 20%.
*   `Flank_Bonus`: Если цель имеет статус `Flanked` $\rightarrow$ **+40% к Криту**.

### 5.3. Расчет Урона (Damage Calculation)
Если попадание успешно, рассчитывается урон.

1.  **Базовый урон (BaseDmg):** Выбирается случайное число `rng.next(Weapon.minDmg, Weapon.maxDmg)`.
2.  **Крит (CritDmg):** Если бросок на Крит успешен, к базовому урону прибавляется `Weapon.critBonus`.
3.  **Броня (Armor):** (В MVP не используется, но резервируем). `Damage = max(1, TotalDmg - Target.Armor)`.

**Пример (Стрелец стреляет из Пищали по Лешему в полуукрытии):**
*   *Дано:* Меткость Стрельца (80). Оружие: Урон 4-6, КритБонус +3, КритШанс 15%. Леший: Защита 0, Полуукрытие (-25%). Высота одинаковая.
*   *HitChance:* $80 + 0 + 0 - 0 - 25 = 55\%$.
*   *CritChance:* $15 + 0 \text{ (нет фланга)} = 15\%$.
*   *Бросок 1 (Попадание):* RNG выдает `42`. $42 \le 55$ $\rightarrow$ ПОПАДАНИЕ!
*   *Бросок 2 (Крит):* RNG выдает `8`. $8 \le 15$ $\rightarrow$ КРИТ!
*   *Бросок 3 (Урон):* RNG выдает число от 4 до 6. Выпало `5`.
*   *Итого:* $5 + 3 \text{ (крит)} = \mathbf{8 \text{ урона}}$.

## 6. Механика Разрушения Окружения (Destruction Math)

*   **Оружие:** Каждое оружие имеет стат `EnvironmentalDamage` (Урон по окружению). Например, Меч = 0, Палица = 2.
*   **Укрытия:** Обладают статом `HP` и `CoverType`.
    *   Вековой дуб (Полное укрытие): `HP = 2`, `CoverType = 2`.
*   **Правило деградации:** Когда атака по площади (или специальная способность "Пролом") наносит укрытие урон, вычитается `EnvironmentalDamage`.
    *   Если `HP` становится $\le 1$, а `CoverType == 2`: укрытие деградирует до `CoverType = 1` (Меняется спрайт на "Разрушенный дуб/пень", штраф к попаданию для прячущегося за ним падает с -50% до -25%).
    *   Если `HP` становится $\le 0$: компонент `Cover` удаляется. Клетка становится открытой.

## 7. Специальные механики (Отбрасывание / Ямы)

Атака "Свист Соловья-Разбойника" или "Удар щитом Богатыря" имеет эффект **Knockback (Отбрасывание)**.

**Алгоритм Knockback:**
1.  Определяется вектор атаки (от Атакующего к Цели).
2.  Цель принудительно перемещается на 1 клетку назад по вектору.
3.  **Collision (Столкновение):**
    *   Если сзади стена/камень: Цель не двигается, но получает **+2 бонусного урона** от удара об стену.
    *   Если сзади обрыв/Яма: Цель перемещается в клетку Ямы. Срабатывает событие `ENTITY_DIED` с причиной `FALL_INTO_PIT`. ХП цели мгновенно приравнивается к 0, игнорируя любые защитные баффы.
