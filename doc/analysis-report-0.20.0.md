# Отчёт: замечания и предложения по исправлению (Bylina Tactics, 0.20.0)

## 1. Несоответствие версии в корневом манифесте

**Проблема**  
В `/app/package.json` указана версия `0.19.0`, хотя все остальные пакеты (`@bylina/*`) имеют версию `0.20.1`, а текущий этап разработки по `doc/roadmap.md` — **0.20.0** (подэтап 5.3 + исправления 0.20.1 / 0.20.2).

**Последствия**  
- Несогласованность при сборке, публикации и проверке CI.  
- `changelog-1.1.md` уже описывает правки 0.20.1 и 0.20.2, а корневой манифест отстаёт.

**Предложение**  
Обновить версию в `/app/package.json` до `0.20.2` (или `0.20.1`).

```json
"version": "0.20.2"
```

## 2. Отсутствие пакета `replay` в описании структуры

**Проблема**  
В `doc/tech-stack.md` и `doc/roadmap.md` (этап 5.4) упоминается функциональность повторов, однако в списке пакетов `doc/tech-stack.md` пакет `replay` не перечислен явно.

**Предложение**  
Добавить в `doc/tech-stack.md` строку:
> `replay` — хранение и воспроизведение логов команд (для повторов и отладки).

## 3. Устаревшая ссылка на improvements.md

**Проблема**  
В `doc/README.md` в таблице назначений указан документ `improvements.md`, однако в актуальной структуре репозитория он отсутствует (или не обновлён после 0.18.0).

**Предложение**  
Либо удалить строку из таблицы, либо создать/обновить документ `doc/improvements.md` с замечаниями по версии 0.20.0.

## 4. Несоответствие в описании этапа 5.3 (онбординг)

**Проблема**  
В `roadmap.md` (раздел 7.3) указано, что 0.20.0 — «Онбординг кампании (выполнен)». При этом в `changelog-1.1.md` подробно описаны правки 0.20.1 и 0.20.2 как часть того же подэтапа.

**Предложение**  
В `roadmap.md` явно указать:
> Подэтап 5.3 завершён в версии **0.20.2** (включая доводки 0.20.1 и 0.20.2).

## 5. Потенциальное отсутствие автоматической проверки словарей

**Проблема**  
В `changelog-1.1.md` (п. 60) говорится об «автоматической проверке полноты словарей». В структуре проекта (`packages/i18n`) такая проверка не обнаружена в скриптах `package.json`.

**Предложение**  
Добавить в `packages/i18n/package.json` скрипт:
```json
"check:i18n": "node scripts/check-dictionaries.js"
```
и интегрировать его в `typecheck` / CI.

## 6. Отсутствие явного признака версии в документации

**Проблема**  
Ни один документ в `doc/` не содержит явного поля «Текущая версия комплекта документации: 0.20.2».

**Предложение**  
Добавить в начало `doc/README.md` после заголовка:
```markdown
**Текущая версия комплекта:** 0.20.2  
**Соответствует версии приложения:** 0.20.2
```

## 7. Риск расхождения между `content` и `campaign`

**Проблема**  
Пакет `campaign` зависит от `content`, но в `campaign/package.json` отсутствует явная зависимость от `@bylina/content` (проверено косвенно через структуру).

**Предложение**  
Убедиться, что в `packages/campaign/package.json` присутствует:
```json
"dependencies": {
  "@bylina/content": "workspace:*"
}
```

## 8. Рекомендация по усилению проверок перед следующим этапом

**Предложения (приоритизация):**

1. Добавить в CI job `version-consistency` (сравнение версий всех `package.json`).
2. Создать smoke-тест запуска приложения с сохранённой кампанией (уже частично сделано в 0.20.2).
3. Добавить проверку наличия всех ключей словарей, используемых в обучении и онбординге.
4. Обновить `doc/tech-stack.md` с актуальным списком пакетов (добавить `replay`, `storage`, `settings`).

---

**Итог:**  
Основная проблема — **рассинхронизация версии** в корневом манифесте. Остальные замечания носит организационный и документационный характер и легко исправимы.
