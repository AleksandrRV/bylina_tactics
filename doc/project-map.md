# Атлас проекта «Былина: Тьма Кощея»

Этот документ — путеводитель по кодовой базе и архитектуре игры. Его цель — быстро сориентировать нового разработчика: объяснить назначение каждого документа спецификации, показать структуру каталогов и дать точный указатель на файлы, где решаются конкретные задачи.

## 2. Структура кодовой базы

Проект организован как монорепозиторий на базе `pnpm workspace`. Код строго разделен на независимые пакеты в `packages/` и готовые приложения в `apps/`.

```
bylina_tactics_agent/
├── doc/                                # Комплект проектной документации
├── .github/workflows/                  # Сценарии автоматизации GitHub Actions (CI и деплой Pages)
└── app/                                # Рабочая область проекта (все команды запускаются отсюда)
    ├── .dependency-cruiser.cjs         # Правила проверки границ слоев и зависимостей модулей
    ├── eslint.config.mjs               # Конфигурация проверок ESLint (включая строгий контроль Promise)
    ├── .prettierrc.json                # Правила форматирования кода (ширина строки 120)
    ├── package.json                    # Корневой манифест (ЕДИНСТВЕННОЕ место объявления версии)
    ├── pnpm-workspace.yaml             # Конфигурация рабочих пространств pnpm
    │
    ├── apps/                           # Запускаемые приложения (конечные точки композиции)
    │   ├── game-pwa/                   # Основной клиент игры: Vite, React, регистрация Service Worker (PWA)
    │   └── signaling-server/           # Легковесный WebSocket-сервер для обмена WebRTC-сигналами (без игровой логики)
    │
    ├── packages/                       # Модули предметных областей (слои архитектуры)
    │   ├── core/                       # Ядро тактического боя: правила, математика, перемещение, ИИ (чистый TS)
    │   ├── campaign/                   # Автомат стратегического режима: прогресс, Летучий Корабль, состав дружины
    │   ├── content/                    # Статические данные (JSON5), схемы валидации (Zod) и загрузчик
    │   ├── session/                    # Оркестратор игрового процесса: сессия, режимы, скрытие данных по туману войны
    │   ├── net/                        # Сетевой транспорт: P2P через WebRTC, локальная шина, упаковка и валидация пакетов
    │   ├── signaling/                  # Клиентская библиотека для подключения к сигнальному серверу
    │   ├── storage/                    # Сохранение в LocalStorage, Web Worker фоновой сериализации, миграция сейвов
    │   ├── replay/                     # Запись команд матча, версионирование правил и воспроизведение реплеев
    │   ├── render/                     # Графический движок поля боя на PixiJS v8: тайлы, эффекты, камера, токены
    │   ├── ui/                         # Интерфейс на React: экраны, HUD боя, диалоги, выбор действий
    │   ├── i18n/                       # Модуль мультиязычности и словари (RU/EN)
    │   └── settings/                   # Хранение пользовательских настроек (звук, язык, подсказки)
    │
    └── scripts/                        # Вспомогательные сценарии сборки и контроля качества
        ├── check-version-consistency.mjs   # Проверка синхронизации версии между package.json и кодом
        ├── set-version.mjs                 # Скрипт атомарного обновления версии одной командой
        ├── visual-audit.mjs                # Проверка контрастности палитры по WCAG и полноты словарей
        ├── capture-screens.mjs             # Снятие и сравнение эталонных скриншотов через Playwright
        └── resize-action-art.mjs           # Пакетная оптимизация и приведение иконок к 512×512
```

## 3. Детальный указатель ключевых файлов

Если вам нужно решить конкретную техническую задачу — обратитесь к соответствующему файлу из таблицы:

### Тактическое ядро и симуляция боя (`packages/core`)
- `src/kernel.ts` — фасад тактического ядра: создание матча, применение команд (`apply`), фазы начала хода, регистрация событий. Здесь же инкрементируется монотонный счетчик ревизии состояния (`revision`).
- `src/combat.ts` — разрешение атак оружием и боевыми навыками: расчет базового шанса, учет высоты, проверка крита, урон и поддержка режимов принудительного попадания/промаха (`forceOutcome`).
- `src/los.ts` — трассировка луча и расчет линии видимости (LOS): определение полного перекрытия или скользящего касания углов препятствий (`glancing`).
- `src/cover.ts` — геометрический расчет укрытий (полные, половинные, граневые) и выявление флангового охвата цели.
- `src/occupancy.ts` — правила проходимости клеток, расчет стоимости ортогонального и диагонального шага с учетом высот и барьеров.
- `src/pathfinding.ts` — алгоритм A* для поиска оптимального пути по сетке с учетом запаса очков передвижения (MP).
- `src/fog.ts` — расчет зоны видимости бойцов и обновление состояния тумана войны (`explored` / `visible`).
- `src/reinforcements.ts` — независимый сервис подкреплений: расчет лимитов врагов, задержки волн и защита от повторного срабатывания за один ход.
- `src/prologue-run.ts` — сценарий выполнения сюжетных миссий: обработка контрольных точек (чекпоинтов), принудительные действия сцен и победные условия.
- `src/cutscene.ts` — декларативные модели кинематографических сцен на поле боя и сопоставление триггеров событий.

### Стратегический режим и метаигра (`packages/campaign`)
- `src/index.ts` — машина состояний кампании: счетчик наступающей Тьмы Кощея, перемещение корабля по глобальной карте, открытие точек сканированием, крафт в Кузне и лечение в Горнице.
- `src/prologue-migration.ts` — логика перевода отряда из обучающего пролога в свободную песочницу с сохранением накопленного опыта.

### Управление сессией и сетевой слой (`packages/session`, `packages/net`, `packages/signaling`)
- `packages/session/src/index.ts` — центральный связующий узел приложения: держит контекст экранов, хранит снимок приостановленной миссии (`suspendedCampaign`), генерирует номер `battleRevision` и фильтрует события для ведомых клиентов по туману войны.
- `packages/net/src/webrtc.ts` — P2P-канал связи на базе браузерного WebRTC: сбор локальных ICE-кандидатов с защитой от зависания по таймауту при отсутствии интернета.
- `packages/net/src/validation.ts` — рубеж безопасности: проверка корректности входящих сетевых команд, лимитов длины путей и размеров снимков мира.
- `packages/signaling/src/index.ts` — клиент WebSocket-сигнализации для состязательного режима через интернет-ретранслятор.
- `apps/signaling-server/src/server.mjs` — автономный сервер обмена SDP-пакетами с лимитами комнат и защитой от переполнения памяти.

### Хранение данных и реплеи (`packages/storage`, `packages/replay`)
- `packages/storage/src/index.ts` — фасад работы с LocalStorage: сохранение кампании, проверка целостности снимка матча (`isMatchSnapshot`) и миграция форматов.
- `packages/storage/src/save-worker.ts` — Web Worker для выноса ресурсоемкой сериализации большого JSON-снимка из главного потока интерфейса.
- `packages/replay/src/index.ts` — запись журнала команд матча, фиксация версий правил (`RULES_VERSION`) и формата (`REPLAY_FORMAT_VERSION`).

### Отрисовка графики (`packages/render`)
- `src/field-renderer.ts` — движок рендеринга на PixiJS v8: процедурная отрисовка изометрического рельефа, тумана, токенов персонажей, плавающих цифр урона и анимаций.
- `src/camera.ts` — математика камеры: масштабирование, кинематографические проезды к целям, панорамирование и расчет видимой области на экранах разного соотношения сторон.
- `src/palette.ts` — эталонные цветовые константы, генератор CSS-переменных темы оформления и визуальные стили биомов.
- `src/token-art.ts` — процедурная векторная отрисовка силуэтов юнитов (Микула, крыса, рекрут) через примитивы PixiJS.
- `src/fringe.ts` — процедурный алгоритм генерации декоративного леса за границами тактической карты.

### Пользовательский интерфейс (`packages/ui`)
- `src/BattleScreenView.tsx` — визуальный экран тактического боя: интеграция с холстом PixiJS, HUD, панели способностей, очереди подсказок и окна диалогов.
- `src/battle-intent.ts` — автомат состояний намерений игрока (`Intent`): единый источник правды для выделения, прицеливания, рывка и перемещения.
- `src/battle-cell-click.ts` — чистая логика интерпретации кликов по клеткам поля (выбор бойца, подтверждение хода, удар, рывок).
- `src/battle-keyboard.ts` — обработчик горячих клавиш клавиатуры (цифры способностей, стойка `9`, дозор `0`, перебор бойцов `Tab`, пауза `Esc`).
- `src/battle-command.ts` — центральный шлюз отправки команд: маршрутизация в локальное ядро или сеть, проверка ограничений пролога и обучения.
- `src/charge-attack.ts` — логика атаки с рывком: одновременный расчет точки подхода и последующего удара в один клик.
- `src/outcome-gate.ts` — таймер задержки показа карточки победы/поражения для завершения всех анимаций и взрывов на поле.
- `src/action-panel.tsx` и `src/action-info.ts` — компактные кнопки действий (512×512 миниатюры) и карточки подробного описания навыка при долгом нажатии.
- `src/unit-card.tsx` и `src/unit-info.ts` — плашки бойцов, полоса противников и модальное окно ТТХ персонажа по долгому тапу.
- `src/use-long-press.ts` — универсальный хук отслеживания долгого нажатия пальцем или правого клика мыши.

### Утилиты и правила качества кода
- `app/.dependency-cruiser.cjs` — архитектурный барьер: запрещает циклические зависимости и импорты из верхних слоев в нижние (проверка запускается через `pnpm check:boundaries`).
- `app/eslint.config.mjs` — линтер проекта: включена строгая типизация Promise (`no-floating-promises`), исключающая тихие сбои асинхронного кода.
- `app/scripts/set-version.mjs` — безопасное обновление версии проекта во всех требуемых манифестах одной консольной командой.
