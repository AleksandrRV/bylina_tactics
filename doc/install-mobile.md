# Установка на телефон для автономной игры
## «Былина: Тьма Кощея», версия 0.20.1

Предмет ведения: публикация собранного приложения через GitHub Actions и GitHub Pages и установка его на мобильное устройство как автономного (offline) приложения. Правила игры и устройство модулей в настоящий документ не входят.

---

## 1. Как это работает

Приложение — PWA (прогрессивное веб-приложение) на `vite-plugin-pwa`. При первом открытии страницы служебный сценарий (service worker) кэширует **все** файлы игры (22 записи, около 1,3 МБ: код, стили, значки, портреты). После этого:

- игра открывается и работает **без сети** — раздача с ПК или сервера не требуется;
- телефон предлагает «установить» игру: появляется значок на домашнем экране, игра запускается в полноэкранном режиме без адресной строки (`display: standalone`);
- при выходе новой версии приложение обновляется само при первом открытии с сетью (`registerType: autoUpdate`).

Единственное, что нужно, — один раз открыть игру по адресу **HTTPS** (требование платформы для service worker). Эту роль выполняет GitHub Pages: сборку туда публикует GitHub Actions, ПК после этого не участвует.

Сетевые режимы (WebRTC, сервер сигнализации) для одиночной игры и кампании не требуются; в автономном режиме доступны быстрый матч, кампания и обучение.

## 2. Разовая настройка репозитория (делается один раз)

### 2.1. Доступность GitHub Pages

GitHub Pages бесплатно доступен только для **публичных** репозиториев. Варианты:

- сделать репозиторий публичным: **Settings → General → Danger Zone → Change visibility → Public**;
- либо оставить приватным — тогда нужна платная подписка GitHub Pro (Pages для приватных репозиториев входит в неё).

### 2.2. Включение Pages через Actions

1. Открыть страницу репозитория на GitHub.
2. **Settings → Pages**.
3. В поле **Build and deployment → Source** выбрать **GitHub Actions** (не «Deploy from a branch»).

### 2.3. Файл рабочего процесса

Готовый текст рабочего процесса лежит в [`doc/deploy-pages.workflow.yml`](deploy-pages.workflow.yml). GitHub не позволяет стороннему приложению создавать файлы в `.github/workflows/`, поэтому его нужно положить на место один раз вручную:

1. На странице репозитория: **Add file → Create new file**.
2. Путь: `.github/workflows/deploy-pages.yml`.
3. Вставить содержимое `doc/deploy-pages.workflow.yml` без изменений и зафиксировать (Commit).

Что делает рабочий процесс:

1. запускается при каждом `push` в `main` (и вручную через **Actions → Deploy PWA to GitHub Pages → Run workflow**);
2. ставит pnpm и Node.js 22, выполняет `pnpm install --frozen-lockfile`;
3. прогоняет тесты (`pnpm test`) — при падении тестов публикации не происходит;
4. собирает приложение с базовым путём `/<имя-репозитория>/` (переменная `BASE_PATH`, её читает `vite.config.ts`);
5. публикует `app/apps/game-pwa/dist` на GitHub Pages.

Ничего дополнительно настраивать в файле не нужно: имя репозитория подставляется автоматически (`github.event.repository.name`), поэтому workflow переживает переименование репозитория и форки.

### 2.4. Первая публикация

1. Слить текущую ветку в `main` (или выполнить `push` в `main`).
2. Открыть вкладку **Actions**, дождаться зелёной галочки у «Deploy PWA to GitHub Pages» (3–5 минут).
3. Адрес игры появится в журнале задания `deploy` и на странице **Settings → Pages**:

```
https://<владелец>.github.io/<репозиторий>/
```

Для этого репозитория: `https://aleksandrrv.github.io/bylina_tactics/`.

## 3. Установка на телефон

### 3.1. Android (Chrome)

1. Открыть на телефоне в Chrome адрес из шага 2.4. Дождаться полной загрузки главного меню (в этот момент service worker кэширует игру).
2. Нажать кнопку установки:
   - либо кнопку «Установить» в самом приложении (появляется, когда обозреватель разрешает установку);
   - либо меню Chrome (⋮) → **Добавить на главный экран** / **Установить приложение**.
3. Подтвердить. На домашнем экране появится значок «Былина».
4. Проверка автономности: включить авиарежим и запустить игру со значка — главное меню, быстрый матч и кампания должны работать.

### 3.2. iPhone / iPad (Safari)

1. Открыть адрес в **Safari** (не в Chrome: на iOS установка PWA доступна только из Safari).
2. Дождаться полной загрузки главного меню.
3. Нажать кнопку «Поделиться» (квадрат со стрелкой) → **На экран «Домой»** (Add to Home Screen) → **Добавить**.
4. Запустить игру со значка хотя бы один раз при включённой сети (закрепляется автономный кэш), затем проверить в авиарежиме.

Замечание для iOS: система может очистить хранилище (включая сохранения в IndexedDB) у веб-приложений, которые долго не открывали. Значок на домашнем экране снижает этот риск, но периодический запуск игры желателен.

### 3.3. Обновление до новой версии

Ничего делать не нужно: после очередного `push` в `main` Actions публикует новую сборку, и при первом запуске игры с доступной сетью приложение скачает и применит обновление автоматически. В авиарежиме продолжает работать прежняя версия.

## 4. Проверка перед выпуском (по желанию, на ПК)

Собрать и посмотреть точно то, что уйдёт на Pages:

```bash
cd app
pnpm install
BASE_PATH=/bylina_tactics/ pnpm build   # PowerShell: $env:BASE_PATH="/bylina_tactics/"; pnpm build
pnpm preview
```

Открыть `http://localhost:4173/bylina_tactics/` и убедиться, что меню, портреты и значки загружаются.

## 5. Возможные отказы и их устранение

| Признак | Причина | Действие |
|---|---|---|
| Страница Pages отдаёт 404 | Источник Pages не переключён на GitHub Actions либо workflow ещё не завершился | Проверить Settings → Pages и вкладку Actions |
| Workflow падает на шаге Deploy с ошибкой прав | Pages не включён или репозиторий приватный без Pro | Выполнить раздел 2.1–2.2 |
| Игра открывается, но без стилей/портретов | Сборка без `BASE_PATH` (пути указывают в корень домена) | Убедиться, что публикация шла через workflow, а не вручную |
| Chrome не предлагает установку | Страница открыта не по HTTPS либо кэш ещё не готов | Обновить страницу, подождать несколько секунд, проверить меню ⋮ |
| На iPhone нет пункта установки | Открыто не в Safari | Открыть адрес в Safari |
| В авиарежиме белый экран | Первое открытие прервано до завершения кэширования | Открыть игру с сетью, дождаться загрузки меню, повторить |

## 6. Что было изменено в проекте для этой схемы

1. `app/apps/game-pwa/vite.config.ts` — добавлена переменная окружения `BASE_PATH` (по умолчанию `/`): она задаёт `base` сборки и `start_url`/`scope` манифеста. Локальная разработка (`pnpm dev`, `pnpm preview`) не изменилась.
2. `doc/deploy-pages.workflow.yml` — рабочий процесс публикации (устанавливается в `.github/workflows/deploy-pages.yml` по разделу 2.3): тесты → сборка с `BASE_PATH=/<репозиторий>/` → копия `index.html` в `404.html` (запасной вход для одностраничного приложения) → выкладка на Pages.
