# Архитектурный Дизайн-документ (Tech Architecture)
## Проект: «Былина: Тьма Кощея»

## 1. Парадигма взаимодействия (Схема потока данных)

```text
[Ввод Игрока (React/Pixi)] 
       │ (1. Создает Команду: ActionCommand)
       ▼
[Session Flow Controller (Дирижер)] ──── (2. Если Мультиплеер) ───> [Network Module (WebRTC)]
       │ (3. Передает команду в Ядро)                                        │
       ▼                                                                     ▼
[Game Core (ECS / Логика)] <──────────────── (Принимает команды от других игроков)
       │ (4. Рассчитывает логику, обновляет State, кидает События)
       ├──────────────────────────────────────────┐
       ▼ (State Update)                           ▼ (Game Events)
[Zustand Stores (Состояние UI)]            [Event Bus (Шина событий)]
       │ (5. Реактивно обновляет UI)              │ (6. Запускает анимации/звуки)
       ▼                                          ▼
[React UI (Меню/HUD)]                      [PixiJS Render (Поле боя)]
```

## 2. Разделение на независимые модули

### 2.1. Модуль Конфигов и Контента (`module-content`)
*   **Ответственность:** Загрузка, валидация и хранение всех статичных данных игры (базовые статы классов, параметры оружия, стоимость зданий). Это "Справочник" игры.
*   **Технологии:** JSON5, Zod (для runtime-валидации).
*   **Взаимодействие:** Инициализируется при старте игры. Предоставляет API вида `getContent('character', 'bogatyr')`.
*   **Зависимости:** Только от файловой системы / бандлера.

### 2.2. Модуль Локализации (`module-i18n`)
*   **Ответственность:** Перевод текстов. Хранит словари (ru, en).
*   **Технологии:** Упрощенный кастомный TS-класс или `i18next`.
*   **Взаимодействие:** Принимает ключи (например, `ui.menu.start`), отдает строку текста. Имеет подписку на смену языка (перерисовывает UI).
*   **Зависимости:** `module-settings` (чтобы знать текущий язык).

### 2.3. Модуль Настроек (`module-settings`)
*   **Ответственность:** Хранение пользовательских настроек (громкость, размер шрифта, режим цветовой слепоты, язык).
*   **Технологии:** Zustand + LocalStorage (через persist middleware).
*   **Взаимодействие:** UI читает из него данные для отображения переключателей; Render читает из него флаги (например, `highContrastMode`).

### 2.4. Модуль Хранения и Сохранений (`module-storage`)
*   **Ответственность:** Запись и чтение динамических данных (Сейвы кампании, логи реплеев, статистика).
*   **Технологии:** Dexie.js (IndexedDB).
*   **Взаимодействие:** 
    *   Предоставляет API: `saveCampaign(state)`, `loadCampaign(id)`.
    *   Сериализует ECS-состояние в JSON при сохранении боя.
*   **Зависимости:** Независим (принимает сырые объекты данных).

---

### 2.5. Модуль Сетевого взаимодействия (`module-network`)
*   **Ответственность:** Передача пакетов между браузерами. Абстрагирует WebRTC от остальной игры.
*   **Технологии:** `simple-peer` (WebRTC DataChannel).
*   **Структура:**
    *   *Signaling Sub-module:* Общение с сервером по WebSocket или генерация/парсинг QR-кодов для обмена SDP-токенами.
    *   *Transport Sub-module:* Универсальный интерфейс `ITransport` с методами `send(command)` и `onReceive(callback)`. Имеет две реализации: `WebRTCTransport` и `LocalTransport` (для одиночной игры или hot-seat).
*   **Зависимости:** Полностью изолирован. Ничего не знает об игре, пересылает только бинарники или JSON-строки.

---

### 2.6. Ядро Кампании / Глобальная Стратегия (`module-core-campaign`)
*   **Ответственность:** Логика Летучего Корабля. Управление ресурсами, счетчик Тьмы Кощея, генерация миссий.
*   **Технологии:** Чистый TypeScript (State Machine).
*   **Подмодули:**
    *   *Squad Sub-module (Дружина):* Учет опыта, ранений, пермадета конкретных персонажей (экземпляров).
    *   *Base Sub-module (Кузня/Горница):* Логика крафта и апгрейдов.
    *   *Map Sub-module:* Генерация точек интереса.
*   **Взаимодействие:** Читает базовые данные из `module-content`, обновляет текущее состояние (которое потом уходит в `module-storage`).

### 2.7. Тактическое Ядро (`module-core-tactics`)
*   **Ответственность:** Вся математика и логика боя. Самый сложный модуль.
*   **Технологии:** `bitECS` (Entity Component System), Seeded RNG (Детерминированный рандом).
*   **Подмодули:**
    *   *Grid Sub-module:* Математика гексов/квадратов, поиск пути (A*), расчет видимости (Raycasting/LOS), высоты, ямы.
    *   *Combat Sub-module:* Расчет попаданий, критов, укрытий, урона.
    *   *AI Sub-module:* Логика поведения нечисти (Utility AI или Behavior Trees). Выдает такие же "Команды", как и живой игрок.
*   **Взаимодействие:** 
    *   **Вход:** Получает сериализованные Команды (`MoveCommand`, `AttackCommand`).
    *   **Выход:** Генерирует События (`EntityMoved`, `DamageDealt`, `Missed`) в `Event Bus`.
*   **Зависимости:** Только `module-content` (для статов оружия/скиллов). **Категорически запрещено** импортировать сюда UI или графику.

---

### 2.8. Модуль Управления Сессией (`module-session` / Flow Controller)
*   **Ответственность:** Главный "Дирижер" (Glue Code). Связывает Ядро, Сеть и Хранилище. Управляет переключением экранов (Меню -> Лобби -> Бой).
*   **Технологии:** TypeScript, State Machine (напр. XState или кастомная).
*   **Роли (Хост/Клиент):** Именно здесь принимается решение:
    *   Если игрок — **Хост**: Сессия принимает команду из UI, скармливает ее в `Tactics Core`, получает результат и через `Network` рассылает клиентам.
    *   Если игрок — **Клиент**: Сессия принимает команду из UI, отправляет ее через `Network` хосту. Ждет, когда по сети вернется обновленный State и События, после чего прокидывает их в UI/Render.

---

### 2.9. Модуль Рендера (`module-render-pixi`)
*   **Ответственность:** Отрисовка тактического боя. Глупый модуль — показывает только то, что ему сказали.
*   **Технологии:** PixiJS (WebGL), gsap (для анимаций).
*   **Подмодули:**
    *   *Tilemap:* Отрисовка сетки, высот, ям.
    *   *Entity Sprites:* Анимация персонажей (idle, run, attack).
    *   *VFX & Particles:* Спецэффекты (взрыв укрытия, вспышки).
*   **Взаимодействие:** 
    *   Подписывается на `Event Bus` из Тактического Ядра.
    *   Пример: Услышал событие `DamageDealt(targetId: 5, amount: 10)` -> нашел спрайт с id 5 -> потряс его (Screen Shake) -> нарисовал всплывающую красную цифру "-10".

### 2.10. Модуль UI (`module-ui`)
*   **Ответственность:** Отрисовка интерфейса (HTML/CSS), захват кликов/тапов игрока.
*   **Технологии:** React 18, Tailwind CSS, Zustand.
*   **Подмодули (Экраны):**
    *   *Menu UI:* Главное меню, настройки.
    *   *Global Map UI:* Интерфейс базы, прокачки, летучего корабля.
    *   *Tactical HUD:* Панель навыков, здоровье, ОД, тултипы на поле боя.
    *   *Lobby UI:* Генерация QR, драфт персонажей.
*   **Взаимодействие:**
    *   Читает данные из глобальных Zustand-сторов.
    *   При нажатии на кнопку "Атака" вызывает функцию `sendCommand(AttackCommand)` из Модуля Сессии.

## 3. Пример взаимодействия модулей (Use Case)

**Сценарий:** Игрок (Клиент в мультиплеере) нажимает кнопку «Выстрел из пищали» по Лешему.

1.  **[module-ui]**: Игрок кликает на иконку выстрела и на врага на экране устройства. React перехватывает клик.
2.  **[module-ui]**: Формирует объект `AttackCommand(source: 2, target: 5, ability: 'pishchal_shot')`.
3.  **[module-session]**: Получает команду. Видит, что игрок — "Клиент".
4.  **[module-network]**: Сессия передает команду в Network. WebRTC отправляет JSON-строку Хосту.
5.  **[module-network] (на устройстве Хоста)**: Принимает пакет, передает в свой `module-session`.
6.  **[module-core-tactics] (у Хоста)**:
    *   Проверяет валидность (Хватает ли ОД? Есть ли линия видимости из `Grid Sub-module`?).
    *   Запрашивает статы оружия из `module-content`.
    *   Бросает Seeded RNG. Попадает! Рассчитывает урон (8 единиц).
    *   Обновляет здоровье Лешего в своем ECS-стейт.
    *   Формирует пакет событий: `[ActionPointsSpent(id:2, 2), HPChanged(id:5, -8)]`.
7.  **[module-session] (у Хоста)**: Забирает результат. Отправляет его обратно Клиенту через `module-network`, а также применяет для своего локального Рендера.
8.  **[module-network] (у Клиента)**: Принимает результат боя.
9.  **[module-render-pixi] (у Клиента и Хоста одновременно)**:
    *   Шина событий публикует `HPChanged(id:5, -8)`.
    *   PixiJS запускает анимацию выстрела у Стрельца, анимацию попадания по Лешему, тряску экрана и всплывающий текст урона.
10. **[module-ui]**: Zustand store обновляется новыми значениями ХП и ОД, React реактивно перерисовывает полоски здоровья.

## 4. Золотые правила разработки (Для команды программистов)

1.  **Никакого DOM в Core.** Модули `core-campaign` и `core-tactics` не имеют права использовать `window`, `document` или любые браузерные API. Это позволяет легко тестировать ядро в Node.js (Vitest) и гарантирует детерминизм.
2.  **Слепой UI.** React-компоненты не должны считать шансы на попадание или проверять дальность. UI должен только запросить данные у `Core` (например, `getHitChance(source, target)`) и отобразить ответ.
3.  **Единый источник истины.** Статы не хардкодятся в коде. Если нужно изменить урон меча, это делается **только** в `assets/configs/weapons.json5`.
4.  **События вместо коллбеков.** Логика не должна ждать, пока закончится анимация выстрела. Ядро мгновенно рассчитывает весь ход и выплевывает массив событий. `Render` проигрывает их последовательно (в очереди).
