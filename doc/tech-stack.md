# Технологический состав
## «Былина: Тьма Кощея», версия 1.1

Предмет ведения: выбранные технологии, устройство репозитория, ограничения платформы и последовательность реализации. Игровые правила и границы модулей в настоящий документ не входят.

---

## 1. Сетевое ограничение платформы

Обозреватель не принимает входящие соединения TCP и UDP. Размещение игрового сервера внутри прогрессивного веб-приложения невозможно.

Принятое решение: канал данных WebRTC между обозревателями, исполнение правил у ведущего участника. Различие между локальной сетью и сетью общего пользования касается только способа установления соединения. Игровые правила на отдельном сервере не исполняются. Для сети общего пользования используется ретранслятор установления соединения и, при необходимости, узел обхода преобразователя адресов.

Наблюдатель запускает то же приложение с ролью наблюдателя и не исполняет правила.

## 3. Устройство репозитория

```
/
├─ doc/                  # нормативная документация
└─ app/                  # исходный код и сборка
   ├─ packages/
   │  ├─ core/
   │  ├─ campaign/
   │  ├─ net/
   │  ├─ signaling/
   │  ├─ render/
   │  ├─ ui/
   │  ├─ content/
   │  ├─ i18n/
   │  ├─ settings/
   │  ├─ session/
   │  └─ replay/
   └─ apps/
      ├─ game-pwa/
      └─ signaling-server/
```

Команды `pnpm` выполняются из каталога `app/`. Пакет ядра не импортирует пакеты канала, изображения и интерфейса.

### 3.1. Хранение

Целевая реализация хранения — `localStorage`, а не IndexedDB: объём одного сохранения кампании и не более 20 повторов не требует отдельной базы данных. Каждая запись содержит независимый от версии приложения `formatVersion` (текущий — 2) и при загрузке проходит через `migrateSave`; неизвестный будущий формат безопасно отклоняется. Перед записью `MatchState`, туман войны и JSON сериализуются в выделенном Web Worker пакета `storage`; главный поток передаёт в `localStorage` уже подготовленную строку. При `QuotaExceededError` запись безопасно отклоняется и не прерывает игру; следующий автосейв сможет повторить попытку.

## 4. Обработка одного действия

1. Участник указывает клетку либо цель. Формируется команда.
2. Команда доставляется ведущему.
3. Ядро ведущего проверяет, применяет, обращается к генератору, формирует события.
4. Каждый получатель воспроизводит адресованный ему набор событий.

---

## 5. Сервер установления соединения

В локальной сети без доступа к внешней сети сервер не требуется.

В сети общего пользования разворачивается указанный ретранслятор: на общедоступной площадке либо как отдельный исполняемый файл для системы Windows. Ретранслятор не исполняет игровые правила.

---

## 6. Платформы поставки

Системы Windows 10 и 11, а также Android: установка прогрессивного веб-приложения из обозревателей Chrome либо Edge.

Автоматическое обнаружение комнат в локальной сети средствами обозревателя невозможно из-за отсутствия широковещательной рассылки. Применяется обмен изображением быстрого считывания либо короткой строкой.
