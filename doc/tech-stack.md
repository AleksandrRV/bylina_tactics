# Технологический стек: тактическая 2D-игра (XCOM2-like PWA)

## Ключевое решение

Браузер не может слушать входящие TCP/UDP-соединения — классический "сервер внутри PWA" невозможен. Решение — **WebRTC DataChannel (P2P)** с моделью **host-authoritative**: один игрок ("Хост") считает игровую логику и рассылает состояние остальным ("Клиентам"). Работает одинаково в LAN и через интернет — разница только в способе первичного соединения (сигналинге). Отдельный Node.js-сервер не нужен — только лёгкий сигналинг-релей для интернет-режима, и то не для геймплея.

Роль "Хост-наблюдатель со статистикой" — тот же PWA, тот же код, просто с ролью `spectator`: обрабатывает всю логику, визуализирует текущее состояние игры в целом.

## Стек по слоям

| Слой | Технология | Зачем |
|---|---|---|
| Язык / сборка | TypeScript (strict) + Vite + `vite-plugin-pwa` | Типизация, офлайн-кэш, установка одним кликом на Windows и Android |
| UI (меню, лобби, HUD) | React 18 + Tailwind + Zustand | Знакомый стек, лёгкий UI-стейт, не хранит игровые данные |
| Игровое ядро | Чистый TypeScript + **bitECS** (ECS-паттерн) | Модульные юниты/статусы/оружие без наследования; ноль зависимостей от DOM, React, сети |
| Рендер поля боя | **PixiJS** (WebGL2) | Быстрый 2D top-down рендер; "глухой" слой — просто отражает состояние ядра |
| Сеть | **WebRTC** (`simple-peer`) | Единственный способ P2P между браузерами |
| Сигналинг (LAN, офлайн) | QR-код (`qrcode`/`jsQR`) или короткий код (`lz-string`) | Обмен SDP вручную, без внешнего сервера |
| Сигналинг (интернет) | Node.js + `ws`, ~100–200 строк, бесплатный хостинг (Fly.io/Render/Railway) | Только "знакомит" пиров и держит список лобби; TURN-фолбэк для сложных NAT |
| Хранилище | Dexie.js (IndexedDB) | Сейвы кампании, реплеи, статистика |
| Конфиги | JSON5 (или YAML) + **Zod**-валидация | Редактируются в любом текстовом редакторе; опечатки ловятся при загрузке, а не крашем |
| Детерминизм | Seeded RNG (без `Math.random()`) | Бесплатные реплеи: seed + лог команд → 100%-точное воспроизведение |
| Тесты | Vitest (ядро) + Playwright (реальный WebRTC-коннект) | |
| Монорепо | pnpm workspaces (+ Turborepo) | Явные границы между модулями |

## Структура проекта

```
tactics-game/
├─ packages/
│  ├─ core/       # ECS, правила, сетка, LOS, seeded RNG — чистый TS, без внешних зависимостей
│  ├─ net/        # ITransport: WebRTC / Local реализации, роли host/client/spectator
│  ├─ signaling/  # QR-обмен и WebSocket-релей для сигналинга
│  ├─ render/     # PixiJS-сцены, спрайты, анимации
│  ├─ ui/         # React-меню, лобби, HUD
│  ├─ content/    # JSON5-конфиги + Zod-схемы
│  └─ replay/     # формат лога команд/событий — общий для сейвов, реплеев, наблюдателя
├─ apps/
│  ├─ game-pwa/          # сборка всех пакетов в единую PWA
│  └─ signaling-server/  # деплой отдельно (облако или локально на Windows)
```

**Правило:** `core` не импортирует ничего из `net`/`render`/`ui` — только эмитит события. Любой слой заменяем без изменения правил игры.

---

## Поток данных (один ход)

1. Игрок кликает клетку в `render` → команда уходит в `net`.
2. `net` доставляет команду Хосту.
3. `core` на Хосте валидирует, применяет, кидает seeded RNG, генерирует события.
4. `render` каждого клиента анимирует полученные события.

---

## Сервер и фолбэк на Windows

- Для **LAN без интернета** сервер не нужен вообще — только ручной QR/код-обмен.
- Для **интернет-игры** — `signaling-server` (Node.js): либо бесплатный облачный хостинг, либо локальный запуск на Windows (`.exe` через `pkg`), если нужна независимость от внешних сервисов.
- Сервер никогда не исполняет игровую логику — только сигналинг и список лобби.

---

## Платформы

- **Windows 10/11**: установка PWA через Chrome/Edge, без доп. ПО.
- **Android**: установка через Chrome, WebRTC и камера для QR работают штатно.
- Полное автообнаружение игр в LAN невозможно в браузере (нет UDP-broadcast/mDNS) — QR/код-обмен закрывает это в рамках веб-платформы.

---

## Этапы разработки

1. `core`: сетка, ход, атака, LOS, seeded RNG — тесты, без графики.
2. `render` + `ui`: играбельный hot-seat через `LocalTransport`.
3. `net` + QR-сигналинг: мультиплеер по Wi-Fi.
4. `content`: вынос баланса в JSON5 + Zod.
5. `spectator`, `replay`, сохранения в Dexie.
6. `signaling-server`: глобальный мультиплеер + TURN.
7. ИИ-бот для одиночной кампании (тот же интерфейс команд, что у игрока).
